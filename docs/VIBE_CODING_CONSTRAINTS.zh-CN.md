# Vibe Coding 前置约束说明

本文件用于人类阅读；真正对编码 Agent 生效的强制规则位于仓库根目录 `AGENTS.md`。

## 开始任何编码前必须确认

1. 当前需求属于 Agent 自主调查、证据治理、受控行动、故障恢复或评测范围。
2. 不涉及模型训练、微调、PPO 或训练数据流水线。
3. 不重复开发密测项目已有的完整报告生成能力。
4. 已写清验收条件、失败条件和权限边界。
5. 已确认改动影响的契约、业务状态、Temporal Replay 和跨语言接口。

## Agent 开发红线

- 不允许让模型直接修改权威业务状态。
- 不允许通过 Prompt 代替服务端权限控制。
- 不允许工具参数携带租户、项目、用户、角色或凭据。
- 不允许只保留聊天记录而不维护结构化调查状态。
- 不允许把“未查询到”直接解释为“不存在”。
- 不允许把模型输出 `done` 作为任务完成依据。
- 不允许没有真实环境复核就关闭风险。
- 不允许多个子 Agent 并发直接修改同一权威状态。
- 不允许静默修复模型 JSON 后继续业务流程。
- 不允许失败后静默切换模型、检索算法或弱化验证标准。

## 多 Agent 约束

- Investigator、Compliance、Verifier 可以串行、并行和重复执行，不是三选一。
- 子 Agent 只能返回结构化 GraphDelta。
- 动态 DAG 必须经过代码校验后执行。
- 同一角色可以启动多个隔离实例，但必须限制最大并发和总预算。
- Verifier 必须独立于被验证结论的完整推理上下文。
- 连续多轮没有新增证据、没有解决问题、没有状态变化时必须终止或转人工。

## 证据约束

每个证据必须有稳定 ID、来源、时间、版本/哈希、时效、工具调用记录和精确引用。结论必须区分事实、推断、不确定性和冲突。

## Temporal 约束

- Workflow 代码保持确定性。
- 模型、数据库、网络、MCP、文件操作全部放在 Activity。
- 有副作用的 Activity 必须幂等。
- 人工输入使用 Signal/Update 和持久等待。
- Workflow 修改必须补 Replay 测试和版本说明。

## 交付完成标准

一次改动只有在以下条件全部满足时才能称为完成：

- 相关契约和文档已更新；
- 权限和权威状态边界未被破坏；
- 正常场景和至少一个对抗场景有测试；
- 关键路径有 Trace/指标；
- 故障、重试和降级行为明确；
- 相关测试通过；
- Diff 中没有无关修改；
- 未通过确定性门禁时不宣称成功。

## 推荐给编码 Agent 的任务模板

```text
目标：

业务背景：

允许修改的模块：

禁止修改的模块：

输入/输出契约：

权威状态归属：

权限与工具范围：

Temporal/事件兼容影响：

验收条件：

失败与降级行为：

必须新增的测试：

必须执行的验证命令：
```

使用该模板可以降低“先写代码再猜需求”的 Vibe Coding 风险。
