# SitePilot 完整项目计划

## 一、项目定位

SitePilot 是一个以 Agent 为核心的智慧工地自主风险调查与处置系统。系统接收人员、设备、安全、质量等风险线索后，不直接给出单一路径结论，而是维护多个竞争假设，主动规划调查任务，调用受控业务工具收集支持和反驳证据，匹配适用规范，提出有边界的处置方案，并在执行后重新观察环境状态，验证风险是否真正解除。

本项目不进行模型训练和微调，不重复建设密测项目已有的报告生成流水线。

与密测项目的互补关系：

- 密测项目：材料摄取、证据检索、章节生成、审核、渲染和报告发布。
- SitePilot：风险感知、动态调查、多 Agent 协同、受控行动、环境反馈和处置闭环。

## 二、核心创新

### 1. 假设—证据—行动图

Agent 的权威状态不是聊天记录，而是版本化图结构：

- Goal：当前调查目标；
- Hypothesis：候选根因及可证伪条件；
- Evidence：带来源、版本、时效和工具调用记录的证据；
- Question：尚未解决、能够区分假设的信息缺口；
- Conflict：互相矛盾或口径不一致的证据；
- Action：候选行动、权限级别和验证条件；
- Constraint：审批、权限、预算和合规约束。

每次 Agent 或子 Agent 执行只返回结构化图增量，由控制器校验并生成新的不可变 GraphRevision。

### 2. 信息价值驱动调查

下一步工具调用不只由模型自由选择，而是综合以下因素排序：

- 能否有效区分多个候选假设；
- 预期证据可靠性；
- 风险紧迫度；
- 工具延迟和模型成本；
- 行动风险；
- 与已有证据的重复程度。

第一阶段采用可解释的启发式评分，不做强化学习。

### 3. 动态多 Agent DAG

Investigator、Compliance、Verifier 不是三选一，也不是固定流水线节点。

- 同一 Investigator 角色可以针对人员、设备、网络、历史记录并行启动多个实例；
- Compliance 可以等待事实确认后执行，也可以发现规范适用条件缺失后触发补充调查；
- Verifier 可在计划、结论和风险关闭三个阶段重复执行；
- 无依赖任务并行，有依赖任务串行；
- LLM 只提出 DAG，代码负责检查环路、依赖、权限、预算和最大并发。

### 4. 调查与行动双循环

调查内循环回答“真实原因是什么”：

```text
提出假设 -> 选择证据任务 -> 调用工具/子 Agent
-> 合并证据 -> 处理冲突 -> 判断是否收敛
```

行动外循环回答“处置后是否真正解决”：

```text
提出行动 -> 系统校验 -> 人工审批 -> 执行
-> 等待观察窗口 -> 重新采集环境证据 -> 验证
-> 关闭或重新调查
```

生成整改建议不等于任务完成。

### 5. 三阶段对抗验证

- Plan Verification：检查假设覆盖、重复任务、工具权限和低价值调用；
- Conclusion Verification：检查反例、证据充分性、时效和逻辑跳跃；
- Closure Verification：检查环境是否真实改变，禁止仅凭整改说明或上传材料关闭风险。

## 三、首批业务场景

### 场景一：疑似无证高处作业

需要区分：证件过期、系统未同步、人员身份识别错误、作业类型不属于特种作业等原因。高风险暂停建议必须有证据并经过审批。

### 场景二：塔吊连续离线

候选原因包括：设备故障、区域网络故障、计划维护、采集服务异常、资产已停用。人员、设备、网络和维护调查可以并行执行。

### 场景三：安全隐患整改逾期

系统需要判断是否提交了有效整改证据、是否只是文字说明、实际环境是否变化；逾期自动升级，复核失败后重新进入整改或调查。

## 四、技术架构

### Java 控制面

采用 Java 17 + Spring Boot 3 模块化单体，负责：

- 项目、风险、证据、整改、审批和审计；
- 身份与项目命名空间；
- 状态机和确定性门禁；
- MCP 工具服务端；
- PostgreSQL 权威状态；
- 事务 Outbox 和事件发布。

### Python Agent Runtime

采用 Python 3.13 + FastAPI + Pydantic，负责：

- Supervisor 调度；
- 假设图维护；
- 信息价值计算；
- 动态 DAG 规划；
- Investigator/Compliance/Verifier；
- MCP Client；
- 结构化模型输出和预算控制。

### Temporal

用于持久化 Agent 长任务：

- 子任务并行；
- Activity 超时和重试；
- 人工补充信息与审批等待；
- 中断恢复；
- 观察窗口 Timer；
- 任务预算和截止时间。

普通 CRUD 和单条事件消费不使用 Temporal。

### 存储和基础设施

- PostgreSQL：业务权威状态、图修订元数据、初期全文/向量检索；
- pgvector：初期规范和案例语义检索；
- MinIO：图片、文档和不可变证据对象；
- NATS JetStream：后续风险线索和事件接入；
- OpenTelemetry：Java、Python、Temporal、MCP 全链路追踪；
- Docker Compose：开发和演示环境。

## 五、权限与行动边界

- L0：只读观察，可自动执行；
- L1：生成草稿和提议，不改变权威状态；
- L2：影响业务的行动，必须通过系统校验和人工审批；
- L3：Agent 永久禁止，包括删除原始证据、修改权限、绕过审批、直接关闭重大风险。

工具参数不得包含 tenant_id、project_id、user_id、角色、凭据、数据库地址和存储根目录；这些信息必须由服务端可信上下文注入。

## 六、开发阶段

### M0：契约和场景

先定义事件、任务、图、证据、图增量、委派、工具结果和行动提议 JSON Schema；完成三个场景及其隐藏真相。

### M1：Java 纵向切片

实现项目、风险、证据、整改模块，数据库迁移、乐观锁、状态门禁、审计和 Outbox。

### M2：Temporal 骨架

实现 InvestigationWorkflow、Activity、人工 Signal、重试、幂等和 Replay 测试。

### M3：MCP 工具体系

实现服务端身份注入、角色工具集、只读工具和提议类工具；完成跨项目和越权测试。

### M4：单 Agent 假设图

实现图模型、图修订、证据边、冲突检测、停止门禁和单 Agent 调查闭环。

### M5：动态多 Agent DAG

实现并行 Investigator、Compliance、三阶段 Verifier、DAG 校验、图增量合并和无进展终止。

### M6：行动与关闭闭环

实现行动分级、审批、幂等执行、观察窗口、关闭验证和重新调查。

### M7：Scenario Gym 与评测

实现隐藏真相、工具模拟、重复/乱序/超时/崩溃注入，输出可复现指标和消融实验。

### M8：可观测和简单前端

实现 Trace、指标、最小管理页面，展示调查图、证据、审批和工作流状态。

## 七、评测指标

### 结果正确性

- 根因识别准确率；
- 风险等级准确率；
- 正确行动或升级率；
- 风险关闭判断准确率。

### 证据质量

- 引用准确率和召回率；
- 必要证据覆盖率；
- 错误主体/错误时间证据率；
- 无证据结论率；
- 冲突发现率。

### Agent 行为

- 必要工具覆盖率；
- 无效工具调用率；
- 平均步骤和成本；
- 过早结束率；
- 无进展循环率；
- 人工升级准确率。

### 可靠性和安全

- 非法工具调用拦截率；
- 跨项目隔离成功率；
- 重复副作用数量；
- 中断恢复成功率；
- 过期证据拦截率；
- 非法结构化输出拒绝率。

## 八、首批消融实验

- 仅聊天历史 vs 假设—证据图；
- 单一最可能原因 vs 竞争假设；
- 模型自由选工具 vs 信息价值评分；
- 固定角色流水线 vs 动态 DAG；
- 无 Verifier vs 结论 Verifier；
- 生成建议即结束 vs 行动后重新观察。

## 九、简历最终可写亮点

项目完成且获得真实评测数据后，重点写：

- 假设—证据—行动图；
- 信息价值驱动的工具选择；
- 动态多 Agent DAG；
- 调查/行动双循环；
- 三阶段对抗验证；
- Temporal 中断恢复和人工等待；
- MCP 最小权限与服务端身份注入；
